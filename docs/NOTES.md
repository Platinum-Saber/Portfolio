# Notes - members-only study guides (`/notes/cse/*`)

Study guides for CSE students at the University of Moratuwa, readable only after signing in with a
`@cse.mrt.ac.lk` Google account. Added 2026-11-07. The architecture follows saai.syvendra.com's
`/notes/cse/s7`; the look does not (neo-brutalist here).

## Routes

| Route                      | What                                                                        | Access  |
| -------------------------- | --------------------------------------------------------------------------- | ------- |
| `/notes`                   | redirects to `/notes/cse`                                                   | -       |
| `/notes/login`             | sign-in card (department email → Google)                                    | public  |
| `/notes/cse`               | all semesters that have at least one guide                                  | members |
| `/notes/cse/sem7`          | course cards for a semester                                                 | members |
| `/notes/cse/sem7/en3330`   | one guide, in the full-screen reader (see "The reader") | members |
| `/notes/cse/sem7/cs4533/labs` | an extra course part (tab), same reader                                 | members |
| `/notes/cse/sem7/cs4533/mock` | mock-paper index; `/mock/<slug>` is the timed online paper              | members |
| `/notes-files/<path>`      | full PDFs (rewritten to `/api/notes/files/...`)                             | members |
| `/api/notes/auth/google`   | starts OAuth (`?next=`, optional `?hint=` email)                            | public  |
| `/api/notes/auth/callback` | Google returns here; mints the session                                      | public  |
| `/api/notes/auth/logout`   | POST only; clears the session                                               | public  |

## Adding a guide

1. Write `content/notes/cse/sem<N>/<slug>.mdx` with frontmatter `code`, `title`, `summary`, `order`,
   optional `sources`, `files`. A new `sem<N>` folder appears on `/notes/cse` automatically.
2. Wrap each section in `<Section id="s1" num="1" title="…" tags="exam calc" pages="…">`. The
   contents panel is read from these tags, so keep `title` in double quotes on the tag itself.
3. Building blocks (`src/components/notes/mdx.tsx`): `Detail` (Detailed view only), `Callout`,
   `Worked`, `Recall` / `RecallList`, `PdfRef file="…" page="N"` (the PDF page index, not the
   printed number). Math is KaTeX: `$…$` and `$$…$$`.
4. **No JS expressions in MDX** - next-mdx-remote v6 blocks them. Write `page="42"`, not `page={42}`.
   A bare `<` or `{` in prose also breaks MDX; keep comparisons inside math.
5. Full PDFs go in `public/notes-files/cse/sem<N>/`; list them in `files`.
6. **Parts (extra tabs)**: list `parts: [{slug, label}]` in the guide's frontmatter and write
   `content/notes/cse/sem<N>/<course>/<slug>.mdx` (frontmatter `title`, `summary`, optional `files`).
   Tabs (Theory / parts / Mock papers) appear above the reader toolbar automatically.
7. **Code files**: `<CodeFile src="cse/sem7/cs4533/code/lab1-ex1.c" cmd="gcc …" from="…" to="…" />`
   reads the file at build time (only compile-tested code goes there; `from`/`to` cut an excerpt).
8. **Mock papers**: list `mocks: [{slug, label}]` and write `<course>/mocks/<slug>.json`
   (`title`, `minutes`, `intro`, `sections[]`; question kinds `mcq`, `fill` with `⟦n⟧` gaps, `order`
   - lines in the correct order, shuffled on screen - `spot` with 1-based line numbers, and `code`
   with a self-marked rubric, and `long` - a structured written question with parts, each with a
   model answer and a tick-box mark scheme, for courses examined by written papers such as MA4144). The paper reaches the browser only in the gated page payload; answers
   and progress live in localStorage. CS4533's papers are generated by a small Python script so the
   MCQ answer letters are shuffled evenly.
   `mockIntro` in the guide frontmatter sets the line under the Mock papers heading (each course
   describes its own exam). Past papers go in the same list: EN3330 has `past-2024` and `past-2025`
   (questions as set, with worked answers, linking the original PDFs in `/notes-files/cse/sem7/`).
9. **Code blocks** look like VS Code (Dark+ in the dark and reading themes, Light+ in light):
   `src/lib/notes/highlight.ts` runs Shiki at build time with only the C and shell grammars,
   for fenced code and `CodeFile`. Add a grammar there only when a guide needs one - each ships
   in the Worker. `CodeFile focus="…" focusTo="…"` shows those lines in Summary and the whole
   file in Detailed; `<Detail>` blocks are the other thing the Summary/Detailed switch hides.
10. **Title pages**: CS4533's PDFs had their first page redrawn with PyMuPDF to match EN3330's layout.

## How the gate works

- **Sign-in:** Google OIDC, authorization code + PKCE + signed state cookie, `hd=cse.mrt.ac.lk` as a
  chooser hint. The callback accepts only a Google-_verified_ address that passes
  `isAllowedEmail()` (`src/lib/notes/email.ts`): `cse.mrt.ac.lk` or a subdomain of it. The email
  typed on the login card is only a hint and an instant check.
- **Session:** no database. An HMAC-SHA256-signed cookie `notes_session` (`{email, name, exp}`,
  HttpOnly, Secure, SameSite=Lax, 7 days). The domain rule is re-checked on every request, so
  tightening it locks out old cookies too. Rotating `NOTES_AUTH_SECRET` signs everyone out.
- **Gate:** `src/middleware.ts` (edge) - matcher `/notes`, `/notes/cse/:path*`, `/notes-files/:path*`
  only. Members-only responses get `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`.
  Edge middleware rather than Next 16's `proxy.ts`: proxy is Node-only and OpenNext's Cloudflare
  adapter marks Node middleware experimental.
- **Pages stay static.** Every notes page is prerendered; the gate decides who receives the prebuilt
  HTML and RSC payload. The guide pages, the gate and the PDF route were all verified in local
  workerd (`npm run preview`).

### Two rules that keep the content private

1. **Guide text lives only in server components.** Anything inside a `'use client'` file ships in a
   public `/_next/static` chunk that the gate does not cover. `GuideShell` and the simulations
   receive content as `children` or hold algorithm code only. Check after a build:
   `grep -rl "<a phrase from a guide>" .next/static` must find nothing.
2. **PDFs are never served straight from the asset store.** `wrangler.jsonc` sets
   `assets.run_worker_first: ["/notes-files/*"]`, so a visitor's request reaches the Worker; the
   middleware rewrites it to `/api/notes/files/...`, which checks the session and reads the bytes
   through the `ASSETS` binding (a binding fetch is not routed back to the Worker). Remove that
   line and the PDFs become public. OpenNext 1.20.16+ also requires `html_handling: "none"` alongside
   it (exact-path assets only) and fails the build without it.

## Secrets

Worker **runtime** secrets (top-level Variables and Secrets panel, or `npx wrangler secret put`),
not build variables. Locally in `.env.local` (`next dev`) and `.dev.vars` (`npm run preview`).

| Name                   | From                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `GOOGLE_CLIENT_ID`     | Google Cloud Console → APIs & Services → Credentials → OAuth client (Web application)                   |
| `GOOGLE_CLIENT_SECRET` | same                                                                                                    |
| `NOTES_AUTH_SECRET`    | 32+ random characters: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"` |

Authorised redirect URIs on the OAuth client:

- `https://sansikawaduge.dev/api/notes/auth/callback`
- `http://localhost:3000/api/notes/auth/callback`
- the `*.workers.dev` preview origin's `/api/notes/auth/callback`, if sign-in should work there

OAuth consent screen: user type **External** (students sign in with the university's Workspace,
not yours), scopes `openid email profile` only - non-sensitive, so no Google verification review.
While the app is in _Testing_, only listed test users can sign in; **publish** it to open sign-in.

**Set up 2026-11-07:** Google Cloud project `study-notes-514005`, OAuth client "sansikawaduge.dev notes"
(redirects: production + localhost:3000), consent screen External and **in production**, branding links
`/notes/login` (home) and `/notes/privacy` (privacy policy - keep it true to the code). Values live in
`.env.local` and `.dev.vars`; push them to the Worker with
`powershell -ExecutionPolicy Bypass -File scripts\notes-secrets.ps1 -Deploy` (one `wrangler secret bulk`,
piped - nothing printed). The client secret cannot be viewed again in the console: to rotate it, add a
new secret on the client, update the two files, re-run the script, then delete the old one.

Without these the notes stay locked (the login card says sign-in is not configured). Nothing else
on the site reads them.

## Simulations and diagrams

`src/components/notes/sims/` - canvas 2D, no dependencies, themed from the `--nb-*` variables:
`DescentLab` (GD, noisy GD, momentum, Nesterov, Adagrad, RMSProp, Adam and Newton on a contour map),
`IntervalSearch`, `WolfeLab`, `NewtonLab`, `CrossEntropyLab` (seeded), `LagrangeLab` and
`PenaltyBarrierLab` (including an augmented-Lagrangian table). `src/components/notes/diagrams.tsx`
holds server-rendered SVG diagrams (no JS). Use them in MDX by name, e.g. `<WolfeLab />`.

## The reader (guide pages)

`src/components/notes/GuideShell.tsx`. A fixed, full-screen layout over the site (the site header is
hidden on every `/notes` route - `Nav.tsx`), with three columns that scroll independently:

- **Left**, flush to the window edge: back link, theme (dark / reading / light), A- A+, the PDF-panel
  toggle, Summary | Detailed, progress, contents (current section highlighted, done ticked), legend,
  sign out. Below 900px it becomes a drawer behind a "Contents" button.
- **Middle**: the guide.
- **Right** (1100px and wider): the original PDF in the browser's own viewer. **Follow** moves it to
  the section being read - each `<Section>`'s first `<PdfRef>` gives its page (`src/lib/notes.ts`).
  Page tags and the PDF cards open here instead of a new tab. The frame is tinted to the theme,
  since the native viewer cannot be styled. The divider between guide and PDF drags (arrow keys
  when focused; double-click or Home resets); the width is kept in `nb-reader-panel-w`.
- Sized to fit a 1920x1080 screen at 100% scaling with nothing scrolling but the guide; at 125-150%
  the contents column scrolls on its own. Scrollbars are styled in notes.css - pseudo-elements for
  Chromium, `scrollbar-color` for Firefox only (Chromium drops the pseudo-elements once it is set).

Remembered per browser: theme and panel (`nb-reader-theme`, `nb-reader-panel`, all guides); mode,
text size and Done ticks (`<code>-v1-*`, per guide). Tables need `remark-gfm` (a dependency since
2026-11-07); without it MDX prints pipe tables as plain text.

## Design

Neo-brutalist, scoped under `.nb` in `src/app/notes/notes.css`, loaded only by the notes layout:
3px ink borders, hard unblurred offset shadows, flat mint/yellow/pink/blue fills, heavy display type,
press-down buttons. It deliberately departs from the console language of docs/DESIGN-LANGUAGE.md -
the notes are a separate product for a different audience.
